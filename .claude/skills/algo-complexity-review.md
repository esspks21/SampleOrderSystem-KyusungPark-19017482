# 알고리즘 복잡도 리뷰 스킬

## 목적

C++ 소스 코드에서 검색·추가·삭제·정렬 등 핵심 연산을 식별하고,
현재 Big-O 복잡도를 분석한 뒤 개선 가능한 알고리즘 또는 자료구조를 제안한다.

## 분석 절차

1. **연산 식별** — 아래 유형의 코드 패턴을 찾는다.
   - 검색: `find`, `find_if`, 선형 순회 `for` 루프
   - 추가: `push_back`, `emplace_back`, `insert`
   - 삭제: `erase`, `remove`, `remove_if`
   - 정렬: `std::sort`, 직접 구현 정렬
   - 집계: `count_if`, 누적 합 등

2. **현재 복잡도 측정** — 각 연산의 최선·평균·최악 Big-O를 표기한다.

3. **병목 판단** — 호출 빈도와 데이터 크기(N)를 고려해 실질적 병목인지 판단한다.

4. **대안 제시** — 개선 가능한 자료구조나 알고리즘을 구체적으로 제안한다.

## 분석 기준표

| 현재 패턴 | 현재 복잡도 | 개선 방향 | 개선 후 복잡도 |
|-----------|------------|-----------|----------------|
| `vector` 선형 검색 | O(N) | `unordered_map` / `unordered_set` | O(1) 평균 |
| `vector` 선형 검색 (정렬된 경우) | O(N) | `std::lower_bound` 이진 탐색 | O(log N) |
| `vector::erase` 중간 삭제 | O(N) | `list` 또는 swap-and-pop | O(1) |
| 중첩 루프 검색 | O(N²) | 해시 테이블 보조 | O(N) |
| 매 호출마다 `std::sort` | O(N log N) | 삽입 시 `std::lower_bound` 위치 유지 | O(log N) 삽입 |
| `count_if` 반복 집계 | O(N) × 호출 횟수 | 카운터 캐싱 | O(1) 조회 |

## 출력 형식

각 이슈에 대해 다음 형식으로 보고한다.

```
[LOCATION]   <파일>:<라인>
[OPERATION]  <연산 종류: 검색 / 추가 / 삭제 / 정렬>
[CURRENT]    <현재 자료구조 및 알고리즘>  →  O(?)
[BOTTLENECK] <병목 여부 및 이유>
[PROPOSAL]   <개선 방안: 자료구조 변경 또는 알고리즘 교체>  →  O(?)
[EXAMPLE]    <적용 코드 예시 (1~5줄)>
```

개선이 필요 없으면: `OPTIMAL — 현재 구현이 최적입니다.`

## 제약

- 동작(로직)은 변경하지 않고 복잡도 개선만 제안한다.
- STL 외 외부 라이브러리는 제안하지 않는다.
- 개선 효과가 미미한 경우(N < 100 등 소규모) 불필요한 교체를 권장하지 않는다.
- 제안 적용 여부는 사용자가 결정한다.
